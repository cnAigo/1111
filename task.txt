【架构师指令：构建精准测试服务化平台 (TaaS Console) MVP版】

当前项目是一个 Spring Boot 工程，请开启完全自治模式，阅读当前项目的代码，并完成以下三个模块的开发：

任务 1：编写后端执行控制器 (TestRunnerController.java)
- 在 src/main/java/org/example/testvue/controller/ 下新建 TestRunnerController。
- 提供一个 POST 接口 /api/test/run，接收参数 module（如：文件夹、用户、全部）。
- 逻辑：根据传入的 module 动态拼接 Maven 测试命令。
- 使用 Java 的 ProcessBuilder 在后台异步执行两条命令：先执行 mvn test，测试完成后，执行 mvn allure:report 生成静态报告。
- 注意：请使用 @Async 异步执行，并立刻给前端返回 "测试已启动" 的 JSON 响应。
● 前端分析与优化建议

  一、单文件巨石 — 首要问题

  770 行全部塞在 App.jsx 里。无组件拆分、无路由库、无自定义 Hook。当前架构：

  App.jsx (770行)
  ├── 25 个 useState
  ├── 12 个 useCallback/useEffect
  ├── 常量/配置数据 (MODULES, MODULE_OPTIONS, MENU_ITEMS...)
  ├── renderSidebar()
  ├── renderHeader()
  ├── renderTerminal()
  ├── renderReport()
  ├── renderResults()
  ├── renderHistory()
  ├── renderFailed()
  ├── renderSettings()
  └── renderConfigModal()

  建议拆分为：

  src/
  ├── App.jsx                    ← 路由 + 全局状态
  ├── components/
  │   ├── Layout.jsx             ← 侧边栏 + 内容区壳子
  │   ├── Sidebar.jsx            ← 导航 + 状态指示
  │   ├── Header.jsx             ← 标题 + 下拉选择器 + 开始/停止按钮
  │   └── Toast.jsx
  ├── pages/
  │   ├── Dashboard.jsx          ← Terminal + Report
  │   ├── Results.jsx
  │   ├── History.jsx
  │   ├── FailedCases.jsx
  │   └── Settings.jsx
  ├── hooks/
  │   ├── usePolling.js          ← 轮询状态逻辑
  │   ├── useTestRun.js          ← 测试执行（start/stop/poll）
  │   └── useConfig.js           ← 配置管理
  └── data/
      └── modules.js             ← MODULES / MODULE_OPTIONS 配置

  二、手写路由 — 应用 react-router

  当前用 activeMenu + if-else 实现页面切换，存在以下问题：

  - 无法收藏/分享特定页面（如 /history）
  - 浏览器后退按钮无效
  - 页面状态在切换时丢失（比如从结果页切回仪表盘再切回来，结果数据没了）

  // 当前
  {page === 'results' && renderResults()}
  {page === 'history' && renderHistory()}

  // 建议
  <Routes>
    <Route path="/" element={<Dashboard />} />
    <Route path="/results" element={<Results />} />
    <Route path="/history" element={<History />} />
    <Route path="/failed" element={<FailedCases />} />
    <Route path="/settings" element={<Settings />} />
  </Routes>

  三、状态管理过于分散

  25 个 useState 平铺在一个组件里，没有分组。相关状态应该聚合：

  // 当前 — 7个独立状态管理测试运行
  const [isRunning, ...] = useState(false);
  const [taskId, ...] = useState(null);
  const [status, ...] = useState('IDLE');
  const [progress, ...] = useState(0);
  const [progressTotal, ...] = useState(0);
  const [durationFmt, ...] = useState('');
  const [runningLabel, ...] = useState('');

  // 建议 — 一个 useReducer 或自定义 hook
  const { isRunning, taskId, status, progress, progressTotal, durationFmt, label,
          startRun, stopRun } = useTestRun();

  同理配置相关 7 个状态也可以抽成 useConfig() hook。

  五、错误处理和边界情况

  // 当前 — 所有错误一视同仁
  const loadHistory = async () => {
    try { const d = await apiGet('/api/test/history'); setHistoryList(d); }
    catch {}  // ← 网络断开、500错误、JSON解析失败，全部静默
  };

  // 建议
  const loadHistory = async () => {
    try {
      const d = await apiGet('/api/test/history');
      if (Array.isArray(d)) setHistoryList(d);
      else setError('返回数据格式异常');
    } catch (e) {
      if (e instanceof TypeError) showToast('网络连接失败，请检查服务是否启动', 'error');
      else showToast('加载失败: ' + e.message, 'error');
    }
  };

  同样的问题在 loadResults、loadFailedCases、loadConfigs 中重复。

  六、性能问题

  6a. 终端日志重渲染

  800 行日志，每行一个 div，每次新增一行全量重渲染。useCallback 包了 appendLog 但由于依赖数组很大，效果有限。

  建议：用 react-window 虚拟列表，或至少用 React.memo 包裹日志行组件。

  6b. pollStatus 1.5 秒一次

  pollRef.current = setInterval(() => pollStatus(d.taskId), 1500);

  如果后端 mvn test 跑 10 分钟，前端会发 400 次 /api/test/status 请求。每次返回的 output 字段是整个控制台输出文本，随测试推进越来越大（可能几MB）。

  建议：后端支持增量输出（传 offset 参数），或者用 WebSocket/SSE 推送替代轮询。

  6c. 计算属性未 memo

  // 每次渲染都重新计算
  const totalR = testResults.reduce(...);
  const passedR = testResults.reduce(...);  // 对同一个数组做了3次 reduce

  建议：useMemo 包裹，一次 reduce 算出全部统计。

  ---
  七、配置管理没有闭环

  这是最核心的功能缺陷：

  用户操作流程：
    打开设置 → 填 URL/项目ID/用户名/密码 → 保存 → 选择模块 → 开始测试

  实际发生的事情：
    保存 ✅  → 选择了模块 ✅  → 开始测试...
    但传给 /api/test/run 的 url/projectId/username/password 被后端丢弃
    实际测试始终跑在 TestConfig.BASE_URL 指向的服务器上

  建议方案：

  ┌───────────────────────────────────────────────┬──────────────────────────────────────────────────────┐
  │                     前端                      │                         后端                         │
  ├───────────────────────────────────────────────┼──────────────────────────────────────────────────────┤
  │ 开始测试时把 configId 传给后端                │ TestExecutionService 用 -DBASE_URL=xxx 传给 mvn 进程 │
  ├───────────────────────────────────────────────┼──────────────────────────────────────────────────────┤
  │ 或者不传 configId，从已保存配置中取当前激活的 │ ProcessBuilder 加环境变量覆盖 TestConfig 的 fallback │
  └───────────────────────────────────────────────┴──────────────────────────────────────────────────────┘

  这样设置页才能真正切换测试目标环境（开发/测试/生产）。
